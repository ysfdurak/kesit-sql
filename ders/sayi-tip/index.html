Tam sayı bölmesi: aynı sorgu, farklı sonuç

İki tam sayıyı böldüğünde sonuç SQL türüne göre değişir. Aşağıdaki sorguyu çalıştır, sonra SQL türü sekmesini değiştirip tekrar çalıştır:

SELECT 7 / 2 AS tam_bolme,
       7 / 2.0 AS ondalikli,
       CAST(7 AS REAL) / 2 AS cast_ile;
SQL türü7 / 2
SQL Server, PostgreSQL, SQLite3 (tam sayı bölmesi)
MySQL, Oracle3.5 (MySQL'de tam sayı bölmesi için DIV)

Oran hesaplarken (dönüşüm oranı, yüzde) bu hata çok yaygındır. Güvenli yol, payı ondalıklı yapmaktır: 100.0 * pay / payda. Böylece her SQL türünde aynı sonucu alırsın.

SQLite'ın esnek tipleriSQLite'ta yalnızca 5 depolama sınıfı vardır (NULL, INTEGER, REAL, TEXT, BLOB) ve tarihler metin olarak saklanır. Diğer SQL türleri tiplerde çok daha katıdır.

CAST ile dönüşüm

SELECT name,
       CAST(price AS INTEGER) AS tam_fiyat,
       CAST(stock AS TEXT) || ' adet' AS stok_metni
FROM products
LIMIT 3;
SQL Server'daCONVERT(tip, değer, stil) ve hata vermek yerine NULL döndüren TRY_CAST / TRY_CONVERT da vardır. Ayrıntılar T-SQL modülünde.
Ondalığı tam sayıya çevirmekSQL Server ve SQLite CAST(2.7 AS INT) sonucunu 2'ye keser; PostgreSQL, MySQL ve Oracle 3'e yuvarlar. Niyetin buysa açıkça FLOOR veya ROUND kullan.
