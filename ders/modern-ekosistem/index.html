NoSQL dalgası ve geri dönüş

2000'lerin sonunda web ölçeği ihtiyacı, şemasız ve yatay ölçeklenen sistemleri doğurdu:

TürÖrnekGüçlü yanı
DokümanMongoDB, CouchbaseEsnek şema, JSON benzeri kayıt
Anahtar-değerRedis, DynamoDBÇok düşük gecikme

Ama analiz yapma ihtiyacı herkesi SQL'e geri getirdi: Hive, Spark SQL, Presto/Trino, Cassandra'nın CQL'i, MongoDB'nin SQL arayüzleri. NewSQL sistemleri (Google Spanner, CockroachDB, TiDB) ise dağıtık ölçeği ACID ve SQL ile birleştirdi.

Bugünün yığını (modern data stack)

  • Bulut veri ambarları: Snowflake, BigQuery, Redshift, Databricks SQL. Depolama ve hesaplama ayrı ölçeklenir.
  • Lakehouse: Veri gölündeki dosyalar (Parquet) üzerinde açık tablo formatları (Delta Lake, Apache Iceberg, Hudi) ile ACID ve SQL.
  • Gömülü analitik: DuckDB, dizüstü bilgisayarda milyonlarca satırı saniyeler içinde sorgular.
  • dbt: SQL SELECT'lerinden oluşan modelleri sürüm kontrolü, test ve dokümantasyonla yönetir. Analytics engineer rolünün temel aracı.
  • Akış (streaming) SQL: Kafka ksqlDB, Flink SQL; sürekli gelen veri üzerinde sorgu.

Yapay zekâ çağında SQL

Doğal dilden SQL üreten araçlar yaygınlaşıyor. Bu, SQL bilmeyi gereksiz kılmıyor; tersine, üretilen sorgunun doğru olup olmadığını (yanlış JOIN, NULL tuzağı, satır çoğalması) anlayabilen insanların değerini artırıyor. Vektör aramaları (pgvector) ve SQL/PGQ graf sorguları da SQL'in kapsamını genişletiyor.
